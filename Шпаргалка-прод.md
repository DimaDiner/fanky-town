# Шпаргалка: прод Funky Town

Сервер: Ubuntu, каталог `/opt/fanky-town`, домен `funky-town-kst.kz`.  
Сервисы: `funky-api` (FastAPI) и `funky-bot` (Telegram).

---

## 1. SSH — вход на сервер

```bash
ssh ubuntu@85.202.192.97
```

Дальше команды, которые меняют систему, — с `sudo` (потребуется пароль пользователя `ubuntu`).

Выход: `exit` или `Ctrl+D`.

---

## 2. Залить доработки на прод

### На компьютере (Windows)

```powershell
cd C:\Users\user\Desktop\fanky-town
git add .
git status
git commit -m "Кратко: зачем изменение"
git push origin main
```

### На сервере (SSH)

```bash
cd /opt/fanky-town
sudo git config --global --add safe.directory /opt/fanky-town   # один раз, если Git ругается на ownership
sudo git pull origin main
source venv/bin/activate
pip install -r requirements.txt
deactivate
sudo systemctl restart funky-api funky-bot
sudo systemctl status funky-api funky-bot --no-pager
```

Короткий вариант (если зависимости не менялись):

```bash
cd /opt/fanky-town && sudo git pull origin main && sudo systemctl restart funky-api funky-bot
```

Проверка: https://funky-town-kst.kz/admin/ и `/start` в боте.

## 3. Мониторинг: живы ли бот и API

```bash
sudo systemctl status funky-api --no-pager
sudo systemctl status funky-bot --no-pager
```

Нужно: `Active: active (running)`.

Логи:

```bash
sudo journalctl -u funky-bot -n 50 --no-pager
sudo journalctl -u funky-api -n 50 --no-pager
sudo journalctl -u funky-api -u funky-bot -f
```

Выход из «живых» логов: `Ctrl+C`.

API с сервера:

```bash
curl -s -w "\nHTTP: %{http_code}\n" --max-time 5 http://127.0.0.1:8000/admin/settings/
```

Ожидание: `HTTP: 200`. Если висит или `000` — API занят или упал.

Сколько процессов бота (должен быть один):

```bash
ps aux | grep run_bot | grep -v grep
```

## 4. Нагрузка сервера (htop)

```bash
htop
```

Выход: `F10`.

| Строка | Норма | Тревога |
|--------|--------|---------|
| **CPU** | 1–20% | долго > 80% |
| **Mem** | до ~70% из ~1 ГБ | > 90% |
| **Swp** | 0K | растёт — кончилась RAM |
| **Load average** | около 0.0x | стабильно > 1 на 1 ядро |

`htop` показывает **сейчас**, не «завис ли запрос». Процесс в состоянии `S` (sleep) с CPU ~0% может ждать сеть — для бота это нормально.

Кто ест память:

```bash
ps aux --sort=-%mem | head -15
df -h
```

## 5. Если бот «молчит»

1. Не смотреть только `htop` — смотреть логи.
2. Типичные строки в `journalctl -u funky-bot`:
   - `httpx.ReadTimeout` / `ConnectTimeout` — API не отвечает (часто после рассылки).
   - `409 Conflict` — запущено два экземпляра бота с одним токеном.
3. Лечение:

```bash
sudo systemctl restart funky-api funky-bot
```

Подождать 10 секунд, в Telegram отправить `/start`.

---

## 6. Рассылка

После отправки в CRM смотреть блок результата: **Отправлено / Ошибок / Без Telegram**.  
Истории рассылок в БД нет — цифры видны только в момент отправки.

Прогресс в логах API:

```bash
sudo journalctl -u funky-api --since "30 min ago" | grep Рассылка
```
