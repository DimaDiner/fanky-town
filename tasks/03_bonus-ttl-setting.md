# Настройка срока жизни бонусов (API)

## Цель

Системная настройка «число месяцев жизни бонусов» читается и сохраняется через существующие эндпоинты настроек.

## Контекст

Настройки — таблица `settings` (ключ/значение). Сейчас разрешены ключи `registration_bonus` и `whatsapp_url` в `PATCH /admin/settings/{key}`. UI админки — отдельная задача 07.

## Требования

1. Ключ: `bonus_ttl_months`.
2. Хелпер `get_bonus_ttl_months(db) -> int` в `crud.py`: если записи нет — создать со значением **3** и вернуть 3.
3. `get_all_settings` должен отдавать ключ (дефолт **3**, если ещё не сохраняли).
4. В `PATCH /admin/settings/{key}` добавить `bonus_ttl_months` в `allowed_keys`.
5. Валидация: целое число **≥ 0**. `0` = бонусы **не протухают** (начисления без `expires_at`, джоб их не трогает).
6. Логика БД только в `crud.py`.

## Затрагиваемые файлы

- `crud.py` — `get_bonus_ttl_months`, при необходимости дефолт в `get_all_settings`
- `main.py` — `allowed_keys` и валидация PATCH

## Критерии приёмки

- [ ] `GET /admin/settings/` содержит `bonus_ttl_months`
- [ ] `PATCH /admin/settings/bonus_ttl_months` с `"3"` сохраняет значение
- [ ] Отрицательное или нечисловое значение → 400
- [ ] Первый вызов хелпера инициализирует **3** в БД
