# Фиксация expires_at в момент начисления

## Цель

Любое начисление бонусов записывает `expires_at = время начисления + N месяцев` из настройки (если N > 0).

## Контекст

Начисления сейчас: регистрация (`create_customer`), ручное массовое (`accrue_bonus_bulk`), касса (`process_transaction` при `amount > 0`). Тип `birthday` в enum есть — если в коде появится начисление ДР, то же правило.

Правила срока:
- **Новые** начисления: `expires_at = момент начисления + N месяцев` из настройки (N > 0).
- **Уже существующие** начисления на момент релиза (положительные транзакции с `expires_at is NULL`): разовый бэкафил `expires_at = сейчас + N` (то же N, что дефолт/настройка на момент миграции, обычно 3). Не `created_at + N`.
- **Смена настройки позже** уже выданные `expires_at` **не** пересчитывает. Новое N только для последующих начислений.

## Требования

1. Общая функция в `crud.py`, например `compute_expires_at(db) -> datetime | None`: сейчас UTC/`datetime.utcnow()` + `bonus_ttl_months` через `dateutil.relativedelta` **или** календарные месяцы через `datetime`/`calendar` без лишней зависимости, если можно обойтись стандартной библиотекой. Одинаково для всех типов начисления.
2. Если TTL = 0 → `expires_at=None`.
3. Проставлять `expires_at` при создании транзакций с `amount > 0` во всех местах начисления.
4. Списания (`amount < 0`) и сторно `expiry` — без `expires_at`.
5. Разовый бэкафил в `crud.py` (вызов из `lifespan` после ALTER и `get_bonus_ttl_months`): все `Transaction` с `amount > 0` и `expires_at is NULL` — выставить `now + N`, если N > 0. Идемпотентно: повторный старт не сдвигает уже заполненные даты.
6. Нельзя иметь код, который при PATCH настройки массово обновляет `expires_at` у старых партий.
7. Баланс не может стать отрицательным (существующие проверки кассы не ломать).

## Затрагиваемые файлы

- `crud.py` — хелпер, начисления, бэкафил существующих партий
- `main.py` — один вызов бэкафила в `lifespan`
- `requirements.txt` — только если добавлен `python-dateutil`

## Критерии приёмки

- [ ] Регистрация с TTL=3 пишет `expires_at` ≈ now+3 месяца
- [ ] Массовое начисление и касса (`amount > 0`) пишут срок от **момента начисления**
- [ ] Списание с кассы не пишет срок
- [ ] При TTL=0 у новых начислений `expires_at` пустой, бэкафил тоже не ставит срок
- [ ] Старые начисления после первого старта получают `сейчас + N`, не `created_at + N`
- [ ] Повторный старт API не сдвигает уже проставленный `expires_at`
- [ ] Изменение настройки в API не массово обновляет старые `expires_at`
