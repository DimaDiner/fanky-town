# Сторно просроченных бонусов

## Цель

Просроченные неиспользованные бонусы списываются с баланса транзакцией типа `expiry` без Telegram-уведомления.

## Контекст

Клиент мог потратить часть партии. Списывать нужно **остаток партии**, FIFO: сначала старые начисления. Нельзя увести баланс ниже 0. Уведомление `notify_customer` / `notify_accrual` для `expiry` **не вызывать**.

## Требования

1. Функция `expire_overdue_bonuses(db) -> int` в `crud.py` (число списанных партий или сумма — задокументировать в docstring).
2. Алгоритм FIFO по клиенту:
   - партии: `amount > 0`, `expires_at` не NULL и `expires_at <= now`, тип не `expiry`;
   - расход: последующие отрицательные транзакции (касса и уже созданные `expiry`) распределять по партиям от старых к новым;
   - если у просроченной партии остаток > 0 — создать `Transaction(type=expiry, amount=-остаток, expires_at=None)`, уменьшить `customer.balance` на этот остаток;
   - если `balance` меньше остатка (рассинхрон) — списать `min(остаток, balance)`, баланс ≥ 0.
3. Партии с `expires_at is NULL` не трогать (TTL=0 или ещё не прошёл бэкафил). После релиза бэкафил (задача 04) проставляет срок существующим начислениям; джоб работает уже по `expires_at`.
4. Идемпотентность: повторный запуск не списывает одну партию дважды (остаток после `expiry` = 0).
5. Запуск:
   - при старте API в `lifespan` (после миграций);
   - периодически: фоновая asyncio-задача раз в 10 минут с отдельной `SessionLocal`;
   - перед списанием/начислением кассы (`process_transaction`) и перед массовым начислением — чтобы касса не тратила уже просроченное.
6. Логика БД только в `crud.py`; в `main.py` только вызов.
7. Клиента **не** уведомлять.

## Затрагиваемые файлы

- `crud.py` — FIFO и сторно
- `main.py` — lifespan + периодический запуск, не вызывать notify на expiry

## Критерии приёмки

- [ ] Просроченная нетронутая партия полностью списывается, в логе транзакций тип «Истечение срока»
- [ ] Если 500 начислено и 200 потрачено FIFO, сторно = 300 (не 500)
- [ ] Баланс не уходит в минус
- [ ] Telegram при сторно не вызывается
- [ ] Повторный прогон не дублирует списание
