# Прошедшие брони серым в календаре

## Цель

Бронь, у которой дата и время окончания уже в прошлом относительно сейчас, в календаре выглядит серой.

## Контекст

Плашки рисует `bookingChip()` в `static/admin.html`. Сейчас цвет только по статусу: draft — синий, confirmed — зелёный, cancelled — серый зачёркнутый. Нужна пометка по **текущим дате и времени** (часовой пояс браузера администратора — достаточно).

## Требования

1. Бронь считается прошедшей, если `date + time_end` **строго меньше** текущего момента.
2. Прошедшие (кроме уже отменённых) — серые, без яркого синего/зелёного. Отменённые оставить как сейчас (серые + зачёркнутые).
3. Не прошедшие — прежние цвета по статусу.
4. Сравнение на клиенте в `bookingChip` (или маленькая функция `isBookingPast(b)`). Бэкенд не обязателен.
5. Легенду календаря дополнить пунктом вроде «Прошедшие», если без неё серый цвет путается с «Отменён».

## Затрагиваемые файлы

- `static/admin.html` — `bookingChip`, блок легенды над календарём

## Критерии приёмки

- [ ] Сегодняшняя бронь с `time_end` в прошлом — серая
- [ ] Сегодняшняя бронь с окончанием в будущем — цвет статуса
- [ ] Завтрашняя бронь не серая из‑за «даты меньше сегодня» целиком без учёта времени на сегодня
- [ ] Отменённые визуально отличаются от просто прошедших (зачёркивание)

**Статус: ОДОБРЕНО**

Задача выполнена корректно. `isBookingPast(b)` сравнивает `date + time_end` строго с текущим моментом (`endAt < new Date()`), формат `HH:MM` из API корректно дополняется до секунд. В `bookingChip` отменённые обрабатываются первыми (серый + зачёркивание), прошедшие — серым без зачёркивания, будущие — цветом статуса. Легенда дополнена пунктом «Прошедшие», «Отменён» визуально отличается зачёркиванием. Все критерии приёмки выполнены, бэкенд не затронут.
